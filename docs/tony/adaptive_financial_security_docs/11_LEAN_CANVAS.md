# 11 — Lean Canvas v0

## Problem

1. La protección antifraude depende parcialmente de reacción rápida del usuario.
2. Autenticación fuerte no demuestra intención segura.
3. Challenges y fallbacks no funcionan igual para todos los contextos y capacidades.

## Existing Alternatives

- push/SMS/email;
- OTP / biometría;
- call center;
- limits;
- transaction monitoring;
- bloqueos;
- branch;
- manual fraud review.

## Customer Segments

### End users
Titulares de cuentas y billeteras digitales.

### Early use cases
- usuarios temporalmente inaccesibles;
- alto riesgo de social engineering;
- dispositivo robado/comprometido;
- usuarios que requieren canales alternativos.

### Buyer
Institución financiera / plataforma de pagos.

### Internal champions
Fraud, Risk, Security, Digital Product, Customer Protection.

## Unique Value Proposition

> **Protect money even when the customer cannot react in time.**

Alternativa en español:

> **Seguridad financiera que sigue funcionando aunque tú no estés mirando.**

## Solution — hipótesis

- policy-based protective hold;
- adaptive verification;
- context aggregation;
- scam-intent interruption;
- accessible recovery;
- evidence timeline.

## Key Metrics

- Time To Protective Action;

- false positive rate;
- challenge completion rate;
- average investigation time;
- support contacts per incident;
- legitimate transaction abandonment;
- accessibility success rate.
